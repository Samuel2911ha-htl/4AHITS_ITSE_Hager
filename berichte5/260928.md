In diesem Bericht wird versucht die Funktionsweise von der Ryuk Ransomware nachzustellen.

## Schnelle Denkarbeit

- Warum AES-256-CBC für das verschlüsseln der einzelnen Dateien?

- Warum ein eigener Key für jede Datei?

- Warum wird dieser AES Key dann RSA verschlüsselt

- Warum an die Datei angehängt?

- Warum wird der victim RSA private Key dann AES verschlüsselt?

- Warum wird ein globaler RSA Key verwendet um aes_victim_key zu verschlüsseln
A: Fragen wurden bereits im Unterricht besprochen.

## Funktionsweise von Ryuk

Es wird für jede Datei ein eigener 256 Bit AES Schlüssel generiert `aes_file_key` und somit die Datei per AES-256-CBC, IV=0 verschlüsselt. `aes_file_key` wird mittels `rsa_victim_key_public` verschlüsselt und das Ergebnis am Ende der verschlüsselten Dartei angefügt. Bei RSA-2048 entsteht 256 Byte Ciphertext, so kann der Entschlüsseler die letzten 256 Byte der Datei als verschlüsselten AES-Schlüssel interpretieren. Jede Originaldatei wird durch die verschlüsselte ersetzt.

`rsa_victim_key_private` für Entschlüsselung benötigt, verbleibt deswegen am Opfersystem. Wird verschlüsselt mit **weiterem AES Key** (`aes_victim_key_private`, AES-256-CBC, IV=0). Dieser Schlüssel wird in `victim_private.enc` abgelegt.

`aes_victim_key` bleibt auch am Opfersystem, deswegen verschlüsseln mit **RSA Masterkey** (`rsa_global_key_public`). Ergebnis wird am Opfersystem abgelegt.

Wenn Lösegeldzahlung --> `rsa_global_key_private` um `aes_victim_key` und damit dann `rsa_victim_kry_private` zu entschlüsseln und alles wiederherzustellen.

## Übung 1.2 (Ryuk - Red Team)

Red Team = Angreifer

Bash Scrript erstellen das mehrere Dateinamen als Argumente akzepiert. Diese werden nach der von Ryuk angewendeten Strategie verschlüsselt. Verwende `openssl`.

Z.B. Alle Dateien im System verschlüsseln

```
$ ryuk_ransom *
```

## Übung 1.3 (Ryuk - Blue Team)

Blue Team = Verteidiger

Nur mit `rsa_global_key_private` entschlüsseln möglich, dieser ist allerdings nur Angreifer bekannt.

Opfer schickt verschlüsselten `aes_victim_key` an Angreifer, nach Lösegeldzahlung schickt dieser `aes_victim_key` entschlüsselt wieder zurück und stellt dem Opfer ein Entschlüsselungstool zur Verfügung.

In 40% der Fälle scheitert nach Zahlung irgendetwas bei der Entschlüsselung.

Ganz selten wird dann der Masterkea des Hackers veröffentlich nach einiger Zeit.

**Aufgabenstellung:**

Lass einige Files von einem Mitschüler verschlüsseln. Versuche nun die Daten selbst wieder zu entschlüsseln mit des Master-Private-Keys.

Implementiere den vollständigen Entschlüsselungsablauf als shell-script mit `openssl`.


# Anhang: AES mit openssl

Mit **Key** und **IV** (im Hex Format)

IV...initialization vector

Verschlüsseln:
```
$ openssl aes-256-cbc -in data.bin -K '0106eb4887051520fcf40b5e8fa5acceab272785c1055ce53e3c201b1d3441fe' -iv '0' -out data.bin.enc
```

Entschlüsseln:
```
openssl aes-256-cbc -d -in data.bin.enc -K '0106eb4887051520fcf40b5e8fa5acceab272785c1055ce53e3c201b1d3441fe' -iv '0' -out data.bin
```

Optionen:
```
-iv IV
    The actual IV to use: this must be represented as a string 
    comprised only of hex digits. When only the key is specified 
    using the -K option, the IV must explicitly be defined.

-K key    
    The actual key to use: this must be represented as a string
    comprised only of hex digits. If only the key is specified, the
    IV must additionally be specified using the -iv option.
```
